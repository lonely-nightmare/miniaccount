# 修复凭证列表金额显示为零

## 功能目标

修复 UI 凭证列表把有分录凭证显示为 `0.00` 的问题。列表金额应等于凭证借方分录合计；草稿和已过账凭证都遵循同一口径。

## 技术方案

- 保留 SQLite `VoucherRepo.List` 只读取凭证头的设计，避免列表查询加载全部分录。
- GUI 使用的 `Service.Vouchers` 从凭证分录按期间汇总借方金额和行数，再填入既有 `VoucherSummary.Amount`、`VoucherSummary.Lines`；MCP 分页路径继续按当前页凭证 ID 汇总。
- 复用服务层已有的 `lineStat` 数据结构；MCP 分页查询 `VouchersPage` 的接口和金额单位保持不变。
- 前端仍接收以分为单位的金额，继续通过 `fmtMoney` 格式化显示；不更改凭证数据或总账。

## 涉及模块

- `internal/service/voucher.go`：GUI 凭证列表的汇总数据来源。
- `internal/service/query.go`：按期间汇总分录借方金额及行数。
- `internal/service/query_test.go`：同时覆盖 GUI 列表与 MCP 分页列表对草稿金额的返回。
- `desktop/frontend/src/views/Vouchers.vue`：仅用于确认既有显示契约，不需要修改。

## 接口设计

对外接口不变。`VoucherSummary.Amount` 仍以分为单位表示借方合计，`Lines` 仍为分录行数；排序、筛选、状态和凭证字段保持原样。

## 数据流

凭证列表查询先从凭证表读取符合筛选条件的凭证头；服务层再按所选期间从 `voucher_entry` 分组汇总每张凭证的借方金额与行数；前端使用原有金额格式化函数显示元。

## 边界条件

- 期间未指定时汇总全账套；指定年或月份时沿用原有期间筛选口径。
- 没有分录的凭证仍显示 `0.00` 和 0 行。
- 草稿、已过账和作废状态的行金额均由实际分录汇总；列表自身的状态筛选继续决定哪些凭证显示。
- 使用按期间的单次聚合查询，不为每张凭证单独查询分录，也不依赖固定数量的 SQL 参数。

## 验证计划

增加服务层回归断言，确认 GUI 列表中的草稿金额和分录行数来自实际分录；随后运行相关单元测试、项目构建，并复查代码差异。
