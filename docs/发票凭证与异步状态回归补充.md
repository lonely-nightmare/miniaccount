# 发票凭证与异步状态回归补充

当前分支已有 `d68f098` 和 `2cecea6`，实现了发票过账参数落库、社保文本编辑、辅助核算类型与名称解析，以及异步响应的初步隔离。本次补齐迁移前发票和并发交互的边界，并为六条问题增加回归覆盖。

## 提交一　发票过账与录入回归

- `service.InvoiceView` 和 Wails 类型返回已保存的 `expenseAccount`、`deptId`。进项发票行打开独立的生成凭证弹窗，以该行 ID 和档案参数初始化，允许旧发票补选部门、重填费用科目。销项发票沿用确认流程。
- 弹窗确认复用 `PostInvoice`。显式参数优先，空参数沿用档案值或已有默认规则。请求失败后保留本次输入供重试，成功后刷新列表。数据表沿用 0016 迁移。旧发票无需重录，当前选择仅用于生成本次草稿。
- 前端冒烟测试覆盖旧发票补部门、新发票预填、社保基数逐字输入和非法值、客户与供应商双重身份、股东、其他往来及同一分录的多维名称。部门列表沿用账套档案；已停用部门仅在该发票已选时回显。

## 提交二　查询与弹窗隔离

- 银行余额调节表在每次查询开始时作废旧序号和结果，包括参数校验提前返回的路径。成功结果与提交时的查询参数一起保存，打印和导出对应屏幕上的结果。空余额仍由后端取流水末笔，显式零仍传零。
- 账期管理每次打开弹窗都新建对象，记录操作类型和账期。预览、体检回包只在对象仍为当前弹窗时生效，覆盖跨账期、同一期重开以及操作切换。结账或反结账完成后只关闭原操作弹窗，并刷新账期。
- 两个页面复用现有 Wails 接口。此提交无模型或数据库变更。
- 使用延迟响应验证无效银行余额可恢复查询，以及同一期重开、跨期切换时旧响应不会覆盖当前结果。

## 验证

每个提交前运行 Go 构建及全量测试、前端构建与 API 测试，并运行相关 GUI 回归。全量 GUI 若出现既有固定资产用例的账期前置条件失败，单独记录。
