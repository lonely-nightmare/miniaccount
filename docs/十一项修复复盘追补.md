# 十一项修复的复盘追补

`ecde8f8` + `8ce960b` 两轮修复后复盘，发现 6 个遗留/新引入的缺陷，
本文档记录问题与修法。

## 1. 银行去重指纹含余额（严重）

`bank.Flow.DedupKey` 的 `fp:` 指纹把 `Balance` 拼接在内。余额不是
交易身份（同一笔流水在不同导出的对账单里余额不同），带来的实际
后果：

- 旧版无余额列导入存的指纹含 `|0|`；新导入带真实余额 → 指纹不同
  → 去重失效**插入重复行**，`8ce960b` 加的「去重命中回填余额」
  永远走不到。
- 余额列本就存在的多次导入：相邻对账单余额读数不同 → 同一笔
  流水从来去不了重（旧版即如此，可能已有重复存量）。

修法：
- 指纹改为 `fp2:` 前缀（避开与旧 `fp:` 串的任何字符级巧合碰撞），
  字段固定为 `日期|方向|金额|对方户名|摘要`，**不含余额**；
  `sn:` 流水号键本就无余额，不变。
- `insertFlow` 去重走两段：先精确匹配 `fp2:`；未命中再扫旧
  `fp:` 候选（`account_id + LIKE 'fp:日期|方向|金额|%'`），
  逐行用库存列重算 `fp2:` 比对 —— 命中即视为重复，
  顺带把 `dedup_hash` 升级成 `fp2:` 并把已知余额回填（治疗
  旧版存错的 0/缺失余额）。
- 存量里已产生的重复流水不自动合并（谁留 voucher 关联无法
  机器判定），文档提示手工清理。

## 2. VerifyOpenable 没有跑迁移 + 丢「是账套」校验

`8ce960b` 把验证改成「临时副本 Open」，但 `sqlite.Open` 只做
`Ping` —— **不跑 `Migrate`**。缺迁移记录的库在迁移时撞重复列
的场景依然验证通过；且丢了旧版的 `book` 表检查，任意合法
sqlite 都能被当成账套恢复。另 `os.ReadFile` 整库读进内存，
大账套恢复时内存峰值 = 整个库大小。

修法：临时副本改流式复制（`io.Copy`），验证走与 `service.Open`
同口径 `Open` → `Migrate` → 查 `book` 行存在 —— 副本开得起
且是账套才算过。

## 3. 删草稿复活作废发票（潜在）

`DeleteDraft` 回退发票状态为 `verified/pending` 的 UPDATE 只按
`voucher_id` 匹配。当前应用没有 booked→voided 入口属潜在问题，
但一旦发票被作废后凭证仍挂 `voucher_id`，删草稿会把它改回
`verified` —— 加 `AND status = 'booked'` 守卫（报销/流水同加
`AND status='posted'` 对称防御）。

## 4. 身份历史起点之前的日期按「当前身份」判

`smallScaleAt`/`smallScaleAtTx` 在 `vat.StatusOn` 未命中时回退
`book.vat_status`（当前值）。早于首条历史记录的日期（账套建立
前的期初凭证）会按「现在」的身份判 —— 一般→小规模切换后，
早于历史起点的凭证被误判为小规模。修法：未命中且日期早于首条
记录时，用**首条记录的身份**（账套建立时的身份）；历史为空才
回退当前登记值。抽 `vat.StatusOnOr` 统一两处语义。

## 5. 工资凭证刷新的准备/应用 TOCTOU

`PrepareStaleDraftRegen`（事务外，T0）到 `ApplyStaleDraftRegenTx`
（过账事务内，T2）之间有窗口：并发 `SaveRun` 在窗口内改写
工资单后，Apply 仍按 T0 快照写分录 —— 过账进总账的数与最终
工资单不一致。修法：Prepare 记录每个 run 的 `updated_at`，
Apply 在事务内逐条复核，不一致即报错让调用方重试（过期数据
永不过账）。

## 6. 附件迁移查询失败完全静默

`migrateLegacyFilesDir` 查 `attachment` 失败时 `return` 无任何
输出 —— 附件静默缺失。改为同样走 stderr 提示（与单文件迁移
失败一致）。

## 实施状态与回归

六项全部修复（2025-11 第三轮）。新增回归：

- `TestImportDedupRepairsLegacyBalance`：手工种旧 `fp:` 指纹 +
  NULL 余额的存量流水，重导带余额的同一笔 → 判重复、余额回填、
  指纹升级 `fp2:`。
- `TestVerifyOpenable`：好账套通过；非账套 sqlite（任意可迁移
  文件）拒绝；删 `schema_migration` 记录导致迁移重演的库拒绝。
- `TestStaleRegenAbortsOnRunModified`：Prepare 后篡改
  `updated_at`，Apply 中止报「被修改」。

## 复盘遗留说明

- **存量重复流水不自动合并**：旧版余额指纹期间已经产生的重复
  `bank_flow` 行仍在库中（哪行保留 voucher 关联无法机器判定）。
  重新导入会逐步自愈指纹，但已存在的重复行需人工核对删除。
- 发票 `booked→voided` 当前无应用入口，作废复活属潜在防御；
  `AND status='booked'` 守卫已就位。
- 工资 `RunUpdatedAt` 用秒级字符串快照，同秒内的双改理论上
  仍有盲区 —— 但 `updated_at` 用 RFC3339Nano，碰撞窗口为纳秒级，
  实务可忽略。
