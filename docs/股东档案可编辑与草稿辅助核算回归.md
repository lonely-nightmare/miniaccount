# 股东档案可编辑 + 凭证草稿辅助核算回归

## 背景（用户报告的两个问题）

1. 辅助核算页建「股东」后，列表里再也找不到它，无法编辑。
2. 带股东辅助的凭证存成草稿后，重开草稿什么都不改直接保存，报
   `第 1 行(3001)：ledger: 缺少必需的辅助核算：科目 实收资本(3001) 要求「股东」，但未填写往来单位`，
   必须重新点选一次股东才能保存。

## 诊断

### 问题 1：真 bug —— 股东/其他档案在界面上不可见

`desktop/frontend/src/views/Auxiliary.vue`：

- `TABS` 只有 customers / suppliers / depts / employees 四个；
- `contactsShown` 只放行 `customer|supplier|both` 三种 kind ——
  kind 为 `shareholder` 或 `other` 的档案**在任何标签页都不显示**；
- 但编辑弹窗的「类型」下拉里又能选 `股东`/`其他单位` —— 用户在客户页
  新建、把类型改成股东，存下去就从这个页面里消失了；
- 新建按钮、往来单位卡片都只在 customers/suppliers 两个标签页渲染。

### 问题 2：当前代码已修复，用户运行的是旧构建

旧版凭证编辑器（8e5e240 之前）`loadVoucher` 把四个辅助 id 全部置 null，
只留下 `_auxDesc` 显示名 —— 界面上股东名照常在，保存时却发出
`contactId: null`，后端 `checkAux`（草稿保存也走 `ValidateDraft`，
见 `internal/domain/ledger/posting.go`）如实拒绝。

8e5e240 已修复（`loadVoucher` 回填 `l.contactId ?? null` 等四维），
且本次新增的 GUI 回归用例「股东草稿重开后原样保存」在完整链路
（建股东 → 存草稿 → 界面点「编辑」→ 原样点「保存草稿」）上验证通过。
代码层面从 `voucher_line.contact_id` 落库、`service.Voucher` 下发、
`VoucherLineRequest` 解码到 `checkAux` 校验逐层核对无误。

## 技术方案

### 前端：`Auxiliary.vue` 补两个往来标签页

- `TABS` 追加 `shareholders`（股东）、`others`（其他往来），
  排在客户/供应商之后、部门之前 —— 四种往来身份相邻；
- `contactsShown` 改为按 `CONTACT_TAB_KINDS` 映射过滤：
  - customers → `customer|both`（沿用，both 是双重身份）
  - suppliers → `supplier|both`
  - shareholders → `shareholder`（后端股东维度只收这个 kind）
  - others → `other`
- `contactKind` 按标签页映射 kind：customers→customer、
  suppliers→supplier、shareholders→shareholder、others→other，
  保证「在股东页点新建」存下来就是股东；
- 新建按钮、往来单位卡片、空态、弹窗标题全部改成由
  `CONTACT_TAB_LABEL` 驱动，四个往来标签页共用一套；
- 编辑弹窗的类型下拉保留全量五种 kind（换类型是合法操作），
  标题按 `KIND_LABEL` 显示当前类型；
- 页首说明从「四个维度」更正为涵盖股东/其他往来。

### 测试

- GUI 回归「股东草稿重开后原样保存不再丢辅助核算」（已加）：
  API 建股东 + 存带 `contactId` 的 3001 草稿 → 校验详情里
  `contactId` 在位 → 界面点「编辑」→ 原样「保存草稿」→
  断言不出现「缺少必需的辅助核算」。
- GUI 回归「股东/其他往来档案在辅助核算页可见可编辑」：
  API 建两种档案 → 界面切到股东页/其他往来页 → 断言行在列表里、
  「编辑」按钮可点 → 改名保存 → API 复核。

### 不做的事

- 不改动 `checkAux` 或任何校验规则；
- 不给 `project` 维度补标签页：项目维度当前无档案表/无选择器
  （`auxPickerItems` 里 project 返回空），属于既有能力边界，
  与本次问题无关。

## 数据流

股东编辑流：股东页 → `editContact(c)`（`kind: c.kind` 原样带入）
→ `saveContact` → `api.saveContact` → `svc.SaveContact`。
新建流：标签页 → `contactKind` 预置 kind → 同上。

## 边界条件

- `both` 档案仍只出现在客户/供应商页（它本来就是「既是客户又是
  供应商」，不是股东）；股东维度后端只收 `shareholder`，前端列表
  与后端 `auxMatchesContact` 保持一致；
- 从客户页新建但把类型改成股东：档案会出现在股东页而不是客户页 ——
  这是「按 kind 归类」的正确行为，用户能找得到；
- 停用/删除/用量检查（`contactUsageOf`）对股东/其他档案同样适用，
  无需额外处理。
