# 侧栏菜单溢出导致整窗滚动

## 现象

窗口高度不足以放下全部菜单项时，向下滚动会把左侧栏的
顶部（logo、首页、凭证、发票、报销）和页头一起滚出屏幕 ——
看起来「整个窗口都在滚」，而不是只有主内容区在滚。

## 根因

`desktop/frontend/src/App.vue`：

- 布局意图是应用外壳：`.flex.h-full` 根容器 = 视口高，
  `main` 用 `min-h-0 flex-1 overflow-auto` 内部滚动，侧栏不动。
- 但 `nav`（菜单容器，`flex-1`）**没有 `overflow-y-auto`，
  也没有 `min-h-0`**：24 个菜单项超出侧栏高度时，溢出部分
  按 `overflow: visible` 直接画到视口外，把文档撑高 ——
  于是 window 自己出现滚动条，侧栏顶部随页面滚走。
- 这正是用户截图里「侧栏上半截消失」的来源。

`html, body, #app { height: 100% }` 链条本身没断
（`height: auto` 那段在 `@media print` 内，与屏幕无关）。

## 修复

1. `nav` 加 `min-h-0 overflow-y-auto`：
   菜单放不下时在**侧栏内部**滚动，logo、收起按钮始终在位。
   `min-h-0` 必须加：flex 子项默认 `min-height: auto`，
   没有它 flex-1 不会收缩到内容以下，overflow 永远不触发。
2. 根容器 `.flex.h-full` 加 `overflow-hidden`：
   应用外壳的保险 —— 任何子树将来再意外撑出内容，
   也只会被裁掉而不再制造窗口级滚动条。
   （Modal/Toast 都 Teleport 到 body，不在此容器内，不受影响。）

## 不改的东西

- `main` 的内部滚动逻辑不动（本来就是对的）；
- `@media print` 的 `height: auto / overflow: visible` 不动
  —— 打印需要展开全文，打印样式与屏幕样式互不干扰；
- 收起侧栏（collapsed）功能不动。

## 验证

- jsdom 无布局引擎，CSS 滚动无法自动化断言；
  在真实应用里把窗口拉矮验证：菜单应在侧栏内自滚，
  logo/收起按钮不消失，主内容区仍只在自己的区域里滚。
- GUI 冒烟全量回归确认无渲染异常。
