# 发票过账参数落库与前端契约二修

对 `8e5e240`（前端契约批）之后验收发现的 6 个问题的修复设计。
前三个为数据正确性问题，后三个为交互健壮性问题。

## 1. 发票过账参数不入库 → 进项票无法生成凭证（高）

**现象**：`post(row)` 改为「仅当表单编辑的是该发票才附
`expenseAccount/deptId`」后，创建表单 `form.id` 恒为 0，
条件永不成立 → 过账永远传空 → 落到默认费用科目 `560206`
（要求部门辅助核算）→ 后端 `ErrMissingAux` 拒绝。

**根因**：`expenseAccount/deptId` 被当成「过账时点参数」，
但发票创建表单让用户录入它们 —— 用户心智里这是发票的属性。
`service.SaveInvoice` 里 `_ = in.DeptID` 的注释承认「生成凭证时用」，
却没有地方存它 —— 设计缺口。

**方案**：把两个参数落库，成为发票档案的一部分。

- 迁移 `0016_invoice_post_params.sql`：
  `invoice` 表 `ADD COLUMN expense_account TEXT NOT NULL DEFAULT ''`、
  `ADD COLUMN dept_id INTEGER REFERENCES department(id)`。
  存量行 `expense_account=''`、`dept_id=NULL` → 回落到默认科目与
  「要求部门则报错」的旧行为，行为不变。
- `invoice.Invoice` 加 `ExpenseAccount string`、`DeptID *int64`；
  `invoiceColumns`/`scanInvoices`/`CreateInvoice` 同步。
- `PostInvoice`：`expenseAccount == ""` 时回落 `inv.ExpenseAccount`，
  `deptID == nil` 时回落 `inv.DeptID`（显式传参仍优先，兼容外部调用）。
- `SaveInvoice`：`inv.ExpenseAccount`/`inv.DeptID` 从输入落库，
  删除 `_ = in.DeptID` 的丢弃行为。
- 前端 `post(row)`：不再传这两个参数（由后端从档案取）。

边界：销项票也存得下这两个字段，但生成凭证路径只在进项方向使用，
行为无影响。旧版程序打开 0016 之后的账套会被版本守卫拒绝——预期行为。

## 2. 社保基数输入框打字即格式化 → 金额静默错（高）

**现象**：`:model-value="centsToYuanInput(baseMin)"` +
`@update` 每次击键回写分；输入 `4` 被立即格式化为 `4.00`，
再按 `5` 得到 `4.005`，保存的是 `4.00`。

**根因**：展示态与编辑态共用同一字段 —— 每次击键都触发
「解析 → 格式化 → 回填」，用户正在输入的中间态被格式化函数吃掉。

**方案**：编辑态独立为字符串。`editScheme` 打开时用
`baseMinYuanText/baseMaxYuanText` 接住 `centsToYuanInput` 的初值；
`v-model` 绑字符串；`saveSchemes` 时 `parseYuanToCents` 一次性
解析回分（空串 → `baseMax` 为 0 即「不限」；无法解析 → 报错不保存）。
费率输入 `ppmToPct` 同病，一并改文本态。

## 3. 辅助核算选择器漏档案（高）

**现象**：`kind === 'customer'/'supplier'` 精确匹配 →
`both` 类型档案被两个列表同时排除；`shareholder`/`other`
维度的科目（如实收资本、其他应收款）根本没有选择器入口。

**后端规则**（`ledger.auxMatchesContact`）：
`customer→{customer,both}`、`supplier→{supplier,both}`、
`shareholder→{shareholder}`、`other→全部类型`。

**方案**：前端 `AUX_LABEL`/`AUX_FIELD` 补 `shareholder`/`other`
（都写 `contactId`）；`auxPickerItems` 按
`CONTACT_KINDS = { customer:['customer','both'],
supplier:['supplier','both'], shareholder:['shareholder'],
other:null（不过滤）}` 过滤，与后端规则一一对应。

## 4. 余额调节页 loading 卡死（中）

**现象**：请求在飞 → 输入无效余额并切换账户 → `load()` 校验
提前 return，但 `reqSeq` 已递增 → 旧响应到达时因序号过期
在 `loading=false` 之前 return → `loading` 永远为 true。

**方案**：两个校验提前 return 分支同时 `loading.value = false`。
（无请求发出就不该停在加载态；正在飞的旧请求的响应反正会被
序号守卫丢弃。）

## 5. 同分录多维度显示错名（中）

**现象**：`pickAux` 只写一份 `l._auxDesc`，`auxChipLabel` 对
任何已填维度都返回它 → 选了客户后，部门按钮也显示客户名。

**方案**：按维度解析。`auxChipLabel` 先 `lookupAuxName(key, id)`
从 `meta` 档案列表按 id 查名（各维各查各的表）；查不到时，
仅当该行**恰好只填了一个维度**才回落 `_auxDesc`（此时它无歧义），
否则显示 `#id`。

## 6. 体检结果覆盖新期间（中）

**现象**：`openClose/openReopen/openHealth` 的响应无条件赋值；
关掉弹窗或换期间后，旧响应仍会覆盖 `preview/health`。

**方案**：赋值前校验 `target` 仍指向发起时的期间且弹窗未关
（`dialog !== null`），不匹配直接丢弃。
